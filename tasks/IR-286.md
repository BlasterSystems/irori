# Task: IR-286 — Network card: directional traffic motion, decluttered labels, layout that follows the card width

Jira IR-286 (local IRI-171), relates to IR-277. Design: `tasks/research-network-card-motion.md`. Mockup: `mockups/IRI-171-network-card.html`. Decision: `docs/adr/0022-directional-flow-colour-token.md` (Accepted 2026-11-27).

## Objective

Turn the Overview Network card into a glanceable live view:
- traffic visibly flows per direction on each cable;
- no text sits on the lines;
- the card lays itself out by its own width, so it never overflows and the table drops below the animation when the card is narrower.

## Product manager summary

- **One-liner:** the Network card shows animated, direction-coloured traffic on every RoCE cable, with a summary and a list that reflow to the card's width.
- **User value:** at a glance, the owner sees whether the fabric is carrying traffic, which way and how much, and whether anything is broken, without reading overlapping labels.
- **Business impact:** completes the IR-273 fabric visibility work. Cluster serving depends on the fabric being healthy.
- **Success metric:**
  - the owner sees motion on busy links and none on idle, stale or down ones;
  - at the owner's ~1150 px card the table sits below the ring;
  - nothing overflows at any width.
- **Dependencies & constraints:** front-end only. ADR-0022 adds one colour token and amends ADR-0018 for that token only. Light and dark themes.

## Acceptance criteria

- [x] No text on or over an edge line. The format string appears once in the subtitle when every link shares it; deviations become edge badges and are shown in the tooltip and table.
- [x] Two direction lanes per cable, coloured by ring direction (`--flow-cw` = thread, `--flow-ccw` blue). Rate pills sit inside the ring with arrows that match the geometry. Non-ring layouts fall back to a → b as "clockwise".
- [x] Particles follow a log mapping of the real per-direction rate (1 Mb/s → 400 Gb/s), eased between samples:
  - no particles below 1 Mb/s;
  - no motion when the data is stale (older than 2.5× the sample interval), a node is offline or the link is down;
  - each of those states looks distinct.
- [x] `prefers-reduced-motion` gives a static encoding. Animation pauses when the tab is hidden or the card is off-screen.
- [x] Header mode badge: `snapshot · 2 s`, `live · <rate>` or `stale · N s`.
- [x] Layout follows the card's own width (container queries at 1280 / 820 / 700 / 600):
  - side by side when wide;
  - table below the animation under 1280;
  - columns dropped under 820;
  - single column under 700;
  - cards under 600.
  No overflow from 340 to 1600 px.
- [x] A summary beside or above the ring: Health, Fabric total, Busiest, Worst RTT.
- [x] The table drops Format, names both directions, shows a log-scale load bar with % of 400G, and puts the last test under Test (wrapping). "Test all fabric links" becomes "Test all links".
- [~] Hovering or focusing an edge, tile or row cross-highlights the others. The edge tooltip shows the details. Rows are keyboard-focusable.
  - **Deviation, owner decision pending:** edges and tiles are hover-only. The keyboard path is the table rows: rows are focusable and cross-highlight the ring. A row carries every tooltip detail except the format, which is shown in the subtitle, or in the row itself on a deviation.
  - The SVG's accessible name lists every link with its rates or state.
- [x] Tests:
  - unit tests for the intensity mapping, ring direction and state derivation;
  - mount tests for no text on edges, badges, hover linking and the summary;
  - a source pin for the container breakpoints and the ADR-0022 tokens;
  - a headless overflow sweep of the real component, as evidence.
  `pnpm test` and `pnpm build` are green.

## Implementation plan

### Key changes

- `flowIntensity(bps)`: `log10(bits/1e6)/log10(4e5)` clamped to 0–1, where `bps` is bytes/s as in the snapshot contract. Then:
  - speed = 18 + 150·t px/s
  - gap = 26 − 18·t
  - opacity = 0.35 + 0.65·t
- `isClockwise(link, order)`: true when b follows a in the ring order (n ≥ 3); otherwise a → b.
- Freshness: the card records the browser time whenever a node's snapshot object changes, which is immune to agent clock skew. A link is stale if node a's last snapshot is older than 2.5× the interval. The interval is 2 s, or the live lease interval while live.
- Link state, in priority order: `down` (0 lanes up), then `offline` (an endpoint is offline), then `stale`, then `idle` (both directions under 1 Mb/s), then `ok`.
- Layout: `container-type: inline-size` on the card, with grid areas `diag / aside / list` switched by `@container`. Remove the old `html[data-tier=small]` diagram hiding.
- The rAF loop runs only while visible (visibilitychange + IntersectionObserver) and not under reduced motion. It eases speed toward the target with dt·3.

### Test approach

- Vitest with happy-dom for the helpers and mounts (existing patterns, real-fleet fixture).
- Happy-dom has no layout engine. Overflow is pinned by a CSS source test and verified by a headless-Chromium sweep of the real component, against the dev hub through the Vite proxy. That sweep is evidence, not CI.

## Review

- **Correctness:** rates come from node a's snapshot (tx = a → b) and are swapped when b → a is the clockwise direction. A mount test covers the swap path (DGX-1 ↔ DGX-4).
- **Freshness:**
  - It uses the store's client receipt times: the new `snapshotAt`, and `netRates.receivedAtMs` for live frames.
  - Each link is judged against the source its rates actually came from (`sampleSource`).
  - Live with no frames, a late frame, or Live off all fall back to the snapshot at the hub's cadence (`cadenceMs`), never an assumed 2 s.
- **Security (`security-check`):** PASS, with no CRITICAL or WARNING findings.

  - Topology strings render only through Vue text interpolation, never `v-html`.

## Completion summary

- **Technical decisions:**
  - The layout uses container queries on the card, not viewport tiers.
  - The rAF loop writes styles directly to the SVG lines, outside Vue's reactivity.
  - Motion uses a log scale from 1 Mb/s to 400 Gb/s.
  - Lanes are coloured by ring direction (ADR-0022).
  - Freshness uses client receipt times recorded at ingest.
- **Known limitations:** edges and tiles are hover-only; the keyboard path is the table rows. The motion scale assumes 2×200G cables; the speed comes from the topology for utilisation only.
- **Deployment notes:** web bundle only. The probe is `/api/v1/version` plus an owner visual check of the Overview Network card on the dev deploy.
