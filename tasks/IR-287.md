# Task: IR-287 — Overview: remove the thermal alert row; hottest token names its sensor (GPU/CPU)

Ticket: [IR-287](https://blastersystems.atlassian.net/browse/IR-287) · local id IRI-172 · branch `feat/iri-172-overview-hottest-source` · research: `tasks/research-overview-thermal-alert-hottest-source.md`

## Objective

Remove the Overview's degraded-only THERMAL alert row and make the page-head `hottest` token say which sensor produced the reading: `hottest DGX-1 CPU 75.8°C`, or `hottest DGX-1 GPU/CPU 75.8°C` on a tie.

## Product manager summary

- **One-liner:** The Overview stops showing a GPU-only thermal warning that contradicted the hottest token, and the token names its sensor.
- **User value:** One consistent answer to "what is hot". No more "hottest DGX-1" next to a warning that names only DGX-3.
- **Business impact:** Less dashboard noise; fewer false impressions of a GPU problem when the hot part is a CPU package.
- **Success metric:** Owner sees a single hottest reading with its sensor named, and no alert row.
- **Dependencies & constraints:** None. Partly reverses the IR-282 alert row (owner decision 2026-11-27).

## Acceptance criteria

- [x] The Overview renders no thermal alert row at any temperature or tier; its computeds and CSS are removed.
- [x] `fleetTemps().hottest` includes `source: "gpu" | "cpu" | "both"`; an exact GPU = CPU tie gives `both`; it stays `null` when nothing reads.
- [x] The page-head token reads `hottest <node> <GPU|CPU|GPU/CPU> <t>°C` and keeps the `hot` tint at ≥ 70 °C.
- [x] Unit tests cover GPU-wins, CPU-wins and a tie; mount and source tests no longer expect the alert row; `pnpm test` and `pnpm build` are green.
- [x] `mockups/overview-adaptive.html` no longer shows the alert row.
